# Pawnder — Setup & Repair Report

This document records what was changed to make Pawnder runnable, and the verification results.

## Environment

- Python **3.12.10** virtual environment at `.venv` (system default is 3.14, which lacks wheels for some dependencies).
- Node 20 / npm 11; frontend dependencies installed; `npm run build` passes.
- **Stockfish 19** (windows x86-64 universal) downloaded from the official GitHub release into `bin/stockfish.exe` (~103 MB, ignored by Git).
- DVC 3.67 installed in the venv. DagsHub remote is configured but authentication was not available; the full pipeline was therefore reproduced locally and `dvc.lock` regenerated (no `dvc push`).
- Live backend and frontend servers are running locally at `http://127.0.0.1:8000` and `http://127.0.0.1:3000`.

## Code changes

### 1. Dependencies (`requirements.txt`)
- Added `torch` via the PyTorch CPU wheel index (previously missing entirely — CI and tests could not import it).
- Added `pyyaml`, **DVC**, `mlflow`, and `dagshub` so the advertised pipeline/tracking stack is installable.

### 2. DVC stages now actually run
- `src/data/chess_com_client.py`: added `load_params()` and a `__main__` entrypoint. It reads `data.username` / `data.max_months`, fetches live games with the correct User-Agent, falls back to local cache, then to a clearly-labeled offline sample.
- `src/data/blunder_detector.py`: added a `__main__` entrypoint. It parses the raw games, runs detection with a **real Stockfish evaluator** (a material-only heuristic can never produce a positive eval drop on the player's own move), deduplicates by FEN, and writes the candidate bank. A labeled fallback seed is written if no blunders are found.
- `dvc.yaml`: added the real deps/params; `params.yaml` gained `engine.depth: 6` and `extract.max_games: 30` so a full run finishes in minutes instead of hours.
- `src/training/train.py`: reads `params.yaml`, builds **real chronological training pairs** via `build_training_pairs_from_bank()` (reusing the extraction stage's engine-verified output instead of re-running Stockfish), falls back to a synthetic sample only when no pairs exist, and stores `candidate_count` + `bank_md5` in the checkpoint.
- `src/training/evaluate.py`: loads the trained checkpoint and evaluates on a chronological 80/20 holdout when enough real pairs exist.

### 3. Real history-conditioned inference
- `src/training/dataset.py`: added `encode_step()`, `encode_history_tensor()`, `build_training_pairs()`, and `build_training_pairs_from_bank()` (leak-free: only strictly earlier blunders become history).
- `src/api/routes/scenario.py`: reads the imported user's `sample_blunders` from `USER_CACHE` and builds the `(1,5,131)` history tensor instead of feeding zeros; caches candidate embeddings per bank version; enforces FEN/color alignment by mirroring the board when needed; separates `player_rating` from `target_elo`.
- `src/api/routes/user.py`: no longer constructs a `BlunderDetector()` without an engine. It reuses the player's existing private bank, merges newly available Chess.com games with the cache, scans **only games that arrived since the previous import** with Stockfish (losses first, up to 12), and always fine-tunes a **fresh** private model from the Lichess base checkpoint. Import now reports games used, games scanned, training pairs, and real blunders.
- `src/api/schemas.py`: `target_elo` is now part of `ScenarioResponse` (legacy request field ignored); `/api/practice/move` requires it instead of silently defaulting to 1400. `result` was added to `PracticeMoveResponse`.
- `frontend/src/services/api.ts` and `App.tsx`: send both ratings; feedback `result` now comes from the actual board result rather than the sign of the evaluation. The username field no longer defaults to `bonc_1` and nothing auto-imports on page load; an empty state prompts for a username instead.
- `frontend/src/components/ChessBoard.tsx` + `frontend/public/pieces/`: the board is now compact and responsive, and renders chess.com-style cburnett PNG pieces (generated by `frontend/scripts/generate-pieces.mjs` via `npm run pieces`) instead of Unicode glyphs.

### 4. Correctness and deployment fixes
- `src/engine/stockfish_manager.py`: honors the `STOCKFISH_PATH` environment variable.
- `src/api/main.py`: removed invalid `allow_origins=["*"]` + `allow_credentials=True` combination.
- `src/api/routes/practice.py`: never reports an engine move that was not actually applied; returns the real game result.
- `models_saved/.gitkeep`: created so `Dockerfile.api` can `COPY models_saved/`.
- `frontend/nginx.conf` + `Dockerfile.frontend`: added an `/api` reverse proxy to `backend:8000` and SPA fallback routing.
- `.gitignore`: ignores `.venv/`, `bin/`, keeps `models_saved/.gitkeep`.
- `src/api/routes/scenario.py`: fixed default candidate whose `player_color` contradicted the FEN side to move.

### 5. Chess.com as main platform + Lichess base dataset + per-user personalization
- `src/config.py`: added `USER_BANK_DIR`, `USER_PROFILE_DIR`, `USER_MODEL_DIR`.
- `src/training/dataset.py`: `CandidateBankManager.for_user(username)` gives each player a private bank and embedding cache; explicit `bank_path` support keeps the Lichess base bank's embeddings separate. `build_training_pairs_from_bank()` accepts a per-game `_target_username` and resets history when the target changes (the base dataset spans many players).
- `src/api/routes/user.py`: imports are **Chess.com only** and write **only** to the player's private bank, persist profiles to disk, feed the player's real rating into history encoding, and fine-tune a private model from chronological pairs. `UserImportRequest.source` was removed.
- `src/api/routes/scenario.py`: a **username is required** (missing → 422) and retrieval only searches that user's own bank (422 if they haven't imported); the private model is preferred over the global checkpoint. The Lichess base bank/model are used only by the DVC pretraining pipeline, never to serve scenarios.
- `src/data/lichess_client.py`: public Lichess NDJSON game-export client with `pgnInJson=true&clocks=true`; normalized PGNs work with the existing `GameParser` unchanged.
- `src/data/lichess_base_ingest.py`, `lichess_base_extract.py`, `src/training/train_base.py`: new base-data stages. Each public Rapid game is tagged with its loser, blunders are extracted into `data/candidate_bank/lichess_base.json` (owner `__base__`), and the global `models_saved/scenario_model.pt` is pretrained from those pairs. `params.yaml` has a separate `base_data` block (`usernames`, `max_games_per_user`, `perf_type`, `max_extract_games`); the old `data.source` switch is gone.
- `src/training/train.py`: `train_personalized_model()` passes `init_from=models_saved/scenario_model.pt`, so every private model **fine-tunes the Lichess-pretrained checkpoint** rather than training from scratch.
- `frontend/src/App.tsx` + `services/api.ts`: the source dropdown was removed; the UI shows a single Chess.com field and `importUser(username)` sends no `source`. Both action buttons stay disabled until a username is entered.
- `tests/test_base_dataset.py`: new tests for loser tagging, base extraction, per-player history isolation, base embedding-cache separation, and fine-tuning from the Lichess checkpoint.

### 6. Username gating + animated moves
- `src/api/routes/scenario.py`: `/api/scenario/predict` now rejects requests without a username (`422`).
- `frontend/src/App.tsx`: both **Import & Practice** and **Generate New Practice Scenario** are disabled until a username is entered. Moves now animate in two phases — the player's move is shown immediately, then Stockfish's reply appears after a **500 ms** pause (`fen_after_player` from the backend makes the intermediate board possible).
- `frontend/src/components/ChessBoard.tsx`: added a flying-piece overlay that slides a piece from its origin square to its destination over 260 ms for **both** the player's and Stockfish's moves; the destination piece is hidden while it flies in.
- Browser-verified: white king and pawn slides, black rook slide, and a 517 ms gap between the two overlays (≈ the intended 0.5 s delay). No console errors.

### 7. Fresh re-import, varied scenarios, and position-aware play
- `src/api/routes/user.py`: re-import no longer short-circuits on an existing bank. It merges live + cached Chess.com games, tracks `analyzed_games`, scans only games present in the live fetch but absent from the **previous cache snapshot** (losses first), marks every scanned game analyzed even when no blunder is extracted, rebuilds the private bank, and retrains a new private model from `models_saved/scenario_model.pt` every time. This fixed `bonc_1` re-imports re-scanning 12 old games each time (blunders grew 29 → 387); after the fix repeated imports stay at 50 blunders / 12 scanned games while still retraining.
- `src/api/routes/scenario.py`: repeated predictions exclude recently served FENs (softmax masking for the neural path; pool exclusion for baseline/fallback), so **Generate New Practice Scenario** now returns different positions. `target_elo` is computed from the selected scenario's real opponent rating/band and clock pressure, plus the player's rating, then clamped/rounded to 1000–2400 in 50-point steps.
- `src/api/schemas.py` + `frontend/src/services/api.ts`: the UI no longer sends a default `target_elo`; the scenario supplies it, and `/api/practice/move` now requires it (`422` otherwise).
- `frontend/src/App.tsx`: scenario-driven Elo display/slider, move-history state, ←/→ replay (plus clickable move chips and replay buttons), and position-aware evaluation/status. The Elo field shows `—` until a scenario loads.
- `frontend/src/components/ChessBoard.tsx`: chess.com-style material advantage numbers above (opponent) and below (player) the board, recalculated from the currently displayed position.
- `frontend/src/components/ClockWidget.tsx`: timeout notification moved out of the `setState` updater to remove a React cross-component update warning; clocks also accept a `resetKey` so reset/scenario-load restarts them cleanly.
- `tests/test_personalization.py` + `tests/test_api.py`: regressions for new-game-only scanning, retraining on every re-import, neural/baseline scenario variation, scenario-derived Elo, and required practice Elo.

### 8. Loading status indicators
- `frontend/src/App.tsx`: separate `isImporting`, `isGenerating`, and `isMoving` flags replace one catch-all loading flag. The import button shows a spinner + **Importing & Training...**, the generate button shows **Generating Scenario...**, the status bar shows submitting/thinking spinners, and the board/empty state shows an overlay with a short explanation while work is in flight.
- `frontend/src/components/WeaknessSummary.tsx`: the audit panel shows a spinning refresh icon plus **Refreshing profile: scanning new games & retraining...** during re-import; the explanatory copy now states that only new games are scanned.
- Browser-verified with `bonc_1`: all three import indicators appeared, four consecutive generated scenarios had four different FENs, a played move showed submitting/thinking states before Stockfish replied, ←/→ replay still worked, and there were no console errors.

### 9. Fast cached imports, Enter shortcut, and chess.com-style board
- `src/api/routes/user.py`: added a 120 s live-fetch cache and a fast path — when no games arrived and the player's bank/profile/checkpoint all exist, the cached profile is returned immediately (`model_reused: true`). New games still force a fresh fine-tune from the Lichess checkpoint. `UserProfileResponse` now carries `model_reused`.
- `src/api/schemas.py` + `frontend/src/services/api.ts`: `model_reused` is exposed to the UI, which reports “private model loaded from cache” vs “retrained”.
- `frontend/src/App.tsx`: pressing **Enter** in the username field starts import & training. The old horizontal evaluation meter was removed; the board now owns a vertical bar.
- `frontend/src/components/ChessBoard.tsx`: piece slide shortened to **160 ms**; history replay now infers the moved piece from FEN differences (including undone captures) and animates both ← and → steps. A vertical evaluation bar sits beside the board, oriented so the player's color is at the bottom.
- Browser-verified: Enter fired `/api/user/import` (44 ms cached), the vertical bar spans the board height, both replay directions produced a flying-piece overlay with `transition: … 160ms`, and no console errors. Direct API timings: first import 20.9 s (fresh retrain), subsequent imports 56 ms and 16 ms (cached).

### 10. Drag-and-drop piece movement
- `frontend/src/components/ChessBoard.tsx`: only the player's own pieces are draggable while it is their turn. `dragstart` transfers the origin square and immediately reveals that piece's legal destinations; `dragover`/`dragenter` highlight the hovered legal square; `drop` reuses the click-to-move UCI construction (including queen auto-promotion) and calls `onMove`. Drag-end clears selection/highlights. Click-to-move is unchanged.
- Browser-verified with `bonc_1`: dragging a black knight from `c6` showed its six legal targets, dropping on one fired `/api/practice/move`, Stockfish replied (`Nxd4`), and a subsequent click-to-move still submitted a move. No console errors.

### 11. Model usefulness evidence
- Added `src/training/evaluate_usefulness.py`: an **offline, chronological 80/20 holdout** for two real users (`bonc_1`: 10 pairs / 51 candidates; `1tshassan`: 19 pairs / 95 candidates). The evaluated model is retrained from the Lichess checkpoint on the earlier 80% only, so no test target is leaked.
- Added a stable learned-similarity term to `ScenarioNetwork.retrieval_logits`: the GRU query is blended with cosine similarity between the most recent blunder's learned board embedding and each private-bank candidate. Checkpoints remain compatible (no new weights).
- Result (`metrics_usefulness.json`): same-failure-category drill **97.4%** vs **78.9%** most-recent, **71.3%** random, **71.1%** hand-rule/majority; board similarity to the later real blunder **0.982** vs **0.789** random / **0.860** recent; top-5 target recall **68.9%** vs ~6.9% chance.
- Negative control: shuffling history/target alignment collapses exact-next-FEN accuracy to **7.9%** (random: 7.6%). The category control stays high because the banks are category-imbalanced; this is documented as a limitation.
- Full narrative, including what the evidence does **not** prove, is in [`MODEL_JUSTIFICATION.md`](MODEL_JUSTIFICATION.md).
